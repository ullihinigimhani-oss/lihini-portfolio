# Lihini Gimhani — Portfolio

Professional responsive portfolio with a **React + Vite frontend** and an **Express API backend**.

## Structure

```
frontend/    React app; deploy to Vercel
backend/     Express API; deploy to Render
```

## Run locally

Open two terminals:

**Terminal 1 — frontend**
```bash
cd frontend
npm install
npm run dev
```

**Terminal 2 — backend**
```bash
cd backend
npm install
cp .env.example .env
npm run dev
```

In local development, the contact form defaults to `http://localhost:5000`. Production uses `VITE_API_URL`, with a `mailto:` fallback if it is absent. You can create a file named `frontend/.env.local` containing:

```env
VITE_API_URL=http://localhost:5000
```

Set `DATABASE_URL` in `backend/.env` to your Neon PostgreSQL connection string. Startup creates `contact_messages` if it does not exist. Submissions are saved before optional SMTP notification; missing or failed SMTP does not discard saved messages. The response confirms storage, not inbox delivery.

## Vercel frontend

1. Import your GitHub repo into Vercel.
2. Set **Root Directory** to `frontend`.
3. Framework preset: **Vite**; build command `npm run build`; output directory `dist`.
4. Deploy. For contact API integration, set `VITE_API_URL` to your Render backend URL and redeploy.

## Render backend

1. New Web Service → connect the same GitHub repo.
2. Set **Root Directory** to `backend`.
3. Runtime: **Node**; build command `npm install`; start command `npm start`.
4. Add environment variables: `DATABASE_URL`, `FRONTEND_URL=https://YOUR-VERCEL-URL.vercel.app`, `CONTACT_EMAIL`, and `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` if you want contact form email delivery. SMTP availability can depend on your Render plan/network policy; otherwise use the `mailto:` fallback.
5. Test `https://YOUR-RENDER-SERVICE.onrender.com/api/health`.

**Never commit SMTP secrets or `.env` files.** Add your actual Vercel URL to `FRONTEND_URL` without a trailing slash. Multiple origins may be comma-separated.

## Database integration checks

From `backend`, run `npm test` for isolated contact API tests and `npm run check:db` for a real database/API check using `.env`. The latter creates the table if needed, verifies an inserted test message inside a transaction, and rolls that test row back. SMTP is disabled during the check.

`GET /api/health/db` returns only connectivity status (503 when unavailable). There is no public endpoint for reading contact messages. The `status` column starts as `received`; it describes message receipt, not SMTP delivery. UUIDs are generated by Node.js. Database connections require certificate-verified TLS and use a bounded connection pool.

For Render, set `PORT`, `DATABASE_URL`, and `FRONTEND_URL` in service environment settings. Use Neon's pooled connection string where appropriate. Set `TRUST_PROXY_HOPS` only after verifying the service's proxy topology so the IP limiter identifies clients correctly. Keep `DATABASE_URL` exclusively in the backend. On Vercel, set only `VITE_API_URL` to the backend's public URL.
## Nodemailer security upgrade

The backend uses Nodemailer 10.5.0 or a compatible patched 10.x release and requires Node.js 20 or newer (local validation used Node.js 22.17.0). Ensure Render uses a compatible Node version. The upgrade from 6.10.1 preserves the existing SMTP `createTransport` / `sendMail` flow. Reviewed breaking changes include SES transport changes (unused here), the `NoAuth` to `ENOAUTH` error-code rename (this API handles errors generically), stricter HTTPS certificate validation (kept enabled), and the Node.js runtime requirement.

Backend tests include real Nodemailer message composition using its in-memory stream transport; this does not connect to SMTP. The live Neon check also disables SMTP and rolls back its test message.
